SwiftOpsBD Swagger API Testing Guide

Complete localhost and deployment verification handbook

OpenAPI 3.1 • 126 operations • Generated 2026-08-01

1. Purpose and safety

Test sequentially because later APIs depend on IDs and states created earlier. This covers Firebase Authentication, Firestore, Supabase private files, Barikoi maps, Stripe test Checkout and all three user roles.

Never enter: Firebase service-account JSON, Stripe/Supabase secrets, real card data, CVV, PIN or OTP. Swagger needs only Firebase ID tokens and test values.

2. Prerequisites and startup

  • Node.js 22+
  • Private backend .env configured and ignored
  • Firebase/Firestore ready
  • Supabase private bucket ready for file tests
  • Barikoi key ready
  • Stripe test keys ready

Backend terminal

cd /d/SoftwareProject/swyftopsbd-api
npm install
npm run dev

Expect: SwiftOpsBD API listening on http://localhost:4000

Stripe terminal (payment phases)

stripe listen --forward-to localhost:4000/api/v1/payments/stripe/webhook

Put its whsec value only in backend .env and restart the API.

3. Swagger site

  1. Open http://localhost:4000/api-docs.
  2. Expand a category and operation.
  3. Click Try it out.
  4. Fill safe path/query/body values.
  5. Click Execute.
  6. Check URL, status and response body.
  7. Save returned IDs privately for later steps.

OpenAPI JSON: http://localhost:4000/api-docs.json

4. Firebase authorization

  1. Log into the frontend as the role being tested.
  2. Open F12 → Network.
  3. Select an API request such as /api/v1/users/me.
  4. In Request Headers copy only the value after Authorization: Bearer.
  5. In Swagger click Authorize, paste only the token, and confirm.

If a call suddenly returns 401, refresh/sign in, copy a new Firebase token and authorize again. Client, caregiver and admin require separate tokens.

5. Status codes

404ID absent or intentionally hidden from this user.

422Read error.fields and correct validation.
500Copy requestId and inspect the API terminal/configuration.

7. Negative security tests

  • No token on protected endpoint → 401.
  • Client token on caregiver/admin endpoint → 403.
  • User A reading user B assignment/document → 403/404.
  • Unsupported or oversized upload → 400.
  • Coordinates outside Bangladesh → validation failure.
  • Unsigned Stripe webhook through Swagger → rejection.
  • Repeat payment/response/complete action → no duplicate record.

8. Final checklist

  • Automated backend tests pass
  • All three role tokens tested
  • Both onboarding workflows approved
  • Real caregiver appears publicly
  • Deposit creates matching request
  • Assignment appears for both users
  • Clock-in/out updates live operations and attendance
  • Private documents reject unrelated users
  • Stripe settles once and invoices download
  • Payout/payslip correct
  • Incident and reports update
  • No secrets entered or committed
